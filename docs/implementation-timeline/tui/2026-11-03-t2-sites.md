# T2: Sites page actions

> Date: 2026-11-03 · Branch: `phase4/t2-sites` · Plan: [Phase 4](../../roadmap/phase-4.md)

## Outcome

- **Per-site menu** (`enter` on a site): open in browser, open the folder in Terminal, copy URL, isolate the PHP version (pick list of installed versions), use the default PHP again (only when isolated), and unlink (only for linked sites, with a y/n confirmation).
- **Page keys:** `a` links a folder (path input, `~` works), `p` parks a folder, `U` unparks one (pick list).
- **Feedback:** every action reports `✓ …` or `✗ <daemon error>` in the footer, and the lists refresh immediately.
- **Design:** key handling stays pure. Actions come out as `Effect`s (daemon request, open URL, open Terminal, copy) that the loop carries out, so every flow is unit-tested without side effects.
- **Daemon:** the `sites` reply also lists `parked` folders, and `Request` derives `Clone`/`PartialEq`.

## Verification

- `cargo test`: 42 tests pass.
  - New unit tests: menu entries per site kind, open/Terminal/copy effects, isolate pick → request, unisolate, unlink confirm (y, n and other keys), link/park input with `~` and backspace, unpark pick and the "no parked folders" message, `~` expansion.
  - New render tests: menu, input, pick, confirm and ✓/✗ messages.
  - The daemon sites test asserts `parked`.
- **pty session against a temp daemon with release PHP 8.4/8.5:**
  - isolate via menu showed "✓ blog now uses PHP 8.4", and `devid sites` shows `PHP 8.4 (isolated)`;
  - link via input showed "✓ linked …/extra/shop";
  - unlink showed the confirmation first, then "✓ unlinked shop", and the site is gone;
  - the TUI exited 0.
- Open-in-browser/Terminal and copy were not run automatically, to avoid opening windows on the owner's Mac; they are covered by unit tests on the effects.
