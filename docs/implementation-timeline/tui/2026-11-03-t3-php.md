# T3: PHP page, Xdebug/pcov toggles, restart

> Date: 2026-11-03 · Branch: `phase4/t3-php` · Plan: [Phase 4](../../roadmap/phase-4.md)

## Outcome

- **Daemon + CLI first (client rule, D-012):**
  - `devid php ext <ver> <xdebug|pcov> <on|off>` writes or removes `conf.d/devid-<ext>.ini` and restarts that version's php-fpm.
  - Xdebug is set up for on-demand debugging: `mode=debug,develop`, `start_with_request=trigger`, port 9003.
  - `devid restart <service>`: the generic restart moved forward from T4, because editing php.ini needs it.
  - `status` reports each version's extensions and php.ini path.
- **TUI PHP page:**
  - lists 8.3/8.4/8.5 (D-009) with php-fpm state, default, Xdebug/pcov ●/○ and pid;
  - `enter` opens the actions for that version: install (when missing, downloaded from the release), make default, Xdebug on/off, pcov on/off, edit php.ini (the TUI steps aside for `$VISUAL`/`$EDITOR`, then restarts php-fpm), restart;
  - `u` checks for updates, `U` updates after a confirmation;
  - "⏳ working…" shows before slow actions.

## Verification

- `cargo test`: 44 tests pass.
  - The new integration test `extensions_and_restart` covers: off by default, on writes the ini with the right `zend_extension` and restarts (new pid), pcov on, off removes it, off twice is fine, unknown extension, version not installed, restart, and restart of a service that is not running.
  - The new unit test `php_page_actions` covers the install-only menu for a missing version, make default, Xdebug on/off by current state, edit+restart, restart, update check and the confirmed update.
- **Real release PHP 8.5 in a temp home:** Xdebug off → on → off was confirmed for both the CLI shim (`extension_loaded`, `php -v` shows Xdebug v3.5.3) and php-fpm through nginx.
- **pty session against a temp daemon:**
  - installed PHP 8.4 from the release through the TUI;
  - turned Xdebug on for 8.5 (`devid-xdebug.ini` present);
  - edited php.ini with a stand-in `$EDITOR` (line saved, "php-8.5 restarted");
  - the update check reported up to date;
  - the TUI exited 0.
- Text inside ratatui's diff-rendered pty output is not reliably contiguous, so the session was checked against daemon state. Message rendering is covered by the `TestBackend` tests.
