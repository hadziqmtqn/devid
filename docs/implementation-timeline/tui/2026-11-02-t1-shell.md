# T1: TUI shell

> Date: 2026-11-02 · Branch: `phase4/t1-shell` · Plan: [Phase 4](../../roadmap/phase-4.md)

## Outcome

- `devid` with no command (when stdout is a terminal) and `devid tui` open the TUI:
  - a header with daemon state, active server, default PHP, site count and version;
  - a sidebar with Sites, PHP, Server, Logs and Settings (`1`–`5`, `↑↓`/`jk`, `tab`, `enter`/`←`);
  - a page area and a footer listing the keys;
  - `?` help, `r` refresh, `q`/`esc`/`ctrl-c` quit.
- Pages in T1 are read-only:
  - Sites: URL, PHP (with "✗ not installed"), folder;
  - PHP: versions with state, pid and default;
  - Server: the active server, ports, the pf note and DNS;
  - Settings: domain, ports, storage, CA, version;
  - Logs: a placeholder until T4.
- When the daemon is not running, the TUI shows a screen that says how to start it (`devid setup` / `devid daemon run`).
- D-017: semantic colors from the terminal palette, a symbol and text for every state, and `NO_COLOR` gives monochrome.
- Status is polled every 2 s only while the TUI is open. `ratatui::init()` restores the terminal on exit and on panic.
- New dependency: `ratatui` 0.30 (crossterm backend).

## Verification

- `cargo test`: 36 tests pass.
  - New unit tests for navigation, help/quit/refresh, header + sidebar + Sites rendering, the other pages and help, the daemon-down screen, and `NO_COLOR` (no cell has a color set; with color, green is used).
  - Rendering uses ratatui's `TestBackend`, so it runs in CI.
- In a pseudo-terminal against the owner's running daemon:
  - the TUI showed the header, `erdbpro-saas.test`, PHP 8.5, help and Settings;
  - it quit with code 0 and entered and left the alternate screen.
- Without a terminal, `devid` prints its help.
- `cargo fmt --check` and `clippy -D warnings` are clean.
