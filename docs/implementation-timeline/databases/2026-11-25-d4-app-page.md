## How a new account goes in the app

1. **Add account** opens the dialog. The database field follows the name until it is edited; MongoDB always has one.
2. **Checks:** the dialog checks the name, the database and a chosen password with the daemon's own rules before it sends `db_user_add`. Errors from the daemon, such as an account that exists already, show in the dialog.
3. **The reply** carries the password and the `.env` lines, and the dialog shows them. Copy password and Copy `.env` go through `copy_db`, which asks the daemon again.
4. **The list** is marked stale, so the next refresh asks for the accounts once.

## Gotchas

- **`go()`** returns at once when the page is already open. The quick menu's Databases items call `pickDb` when the page is already open.
- **The page's data:** `renderPage()` draws from the data that `refresh` loaded. A state that changes between refreshes, such as the download's progress, must be read from `S` directly.
- **Disabled menu items:** WebKit may show no `title` tooltip on a disabled button. The reason is still in its `title` for assistive technology.
