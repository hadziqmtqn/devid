## How a new account goes in the app

1. **Add account** opens the dialog. The database field follows the name until it is edited; MongoDB always has one.
2. **Checks:** the dialog checks the name, the database and a chosen password with the daemon's own rules before it sends `db_user_add`. Errors from the daemon, such as an account that exists already, show in the dialog.
3. **The reply** carries the password and the `.env` lines, and the dialog shows them. Copy password and Copy `.env` go through `copy_db`, which asks the daemon again.
4. **The list** is marked stale, so the next refresh asks for the accounts once.

## Open in Terminal (the owner's change after the preview)

The owner asked for it after the preview: a button that opens the database in a terminal, with a choice that includes cmux, landing at the client's prompt.

- **`crates/gui/src/api.rs`:**
  - `terminals()` reads `/System/Applications/Utilities`, `/Applications`, `/Applications/Utilities` and `~/Applications`:
    - `terminal_name` skips an app whose `Info.plist` lacks the bytes `Shell`;
    - for the rest, `plutil -extract CFBundleDocumentTypes json` gives the types, and `runs_scripts` looks for the `Shell` role on `com.apple.terminal.shell-script`, `public.shell-script` or the extension `command`;
    - on the M1, 3 apps got past the byte check, and Terminal and cmux were kept.
  - `open_db_client(engine, app)`:
    - checks the app with `terminal_name` and the server's state with `status`;
    - writes `run/devid-<engine>.command` from `client_files` and opens it with `/usr/bin/open -a <app>`;
    - the script `exec`s the shim (`bin/mysql`, `bin/psql` or `bin/mongosh`), and exports `DEVID_HOME` when the app has one.
  - **MongoDB:**
    - `db env` gives `root`'s password;
    - `run/devid-mongosh-<time>.js` (mode 0600, `create_new`) unlinks itself, then runs `db.getSiblingDB('admin').auth(…)`;
    - the `.command` runs `mongosh --shell --file <js>`, then `rm -f <js>`. The file is also removed when `open` fails.
  - `sh_quote` quotes for `sh`, and `in_terminal` uses it too.
- **`crates/gui/ui/app.js` and `app.css`:**
  - `loadTerminals` asks once and reads the last pick from `localStorage` (`devid.terminal`);
  - `dbTerminalBtn` draws the button with its ▾ (`.dv-split`), and `openDbClient` remembers the pick;
  - `ICONS.terminal` is the button's icon;
  - the Terminal row's (i) changes while Devid's commands are off PATH.
- **`build.rs`, `capabilities/main.json` and `main.rs`:** `terminals` and `open_db_client` are allowed and registered.
- **Tests:**
  - `terminal_apps_run_command_files`;
  - `terminals_come_from_the_app_folders_terminal_first` (macOS only, uses `plutil`);
  - `a_client_runs_through_its_shim`;
  - `mongodb_logs_in_from_a_file_not_the_command_line`.

## Gotchas

- **A pty without a size:** psql pages even one row through `less` when the terminal has 0 rows, so a test driver must set the window size (`TIOCSWINSZ`). A real terminal window has one.
- **cmux and `.command` files:** cmux types the file's path into a new workspace's shell. When the client quits, that shell stays open in `~/.devid/run`. Terminal runs `path; exit` and ends the window's shell.
- **mongosh with `--file`:** it prints `Loading file: …` with the login script's path, which is already gone by then. Its telemetry notice is mongosh's own.
- **`go()`** returns at once when the page is already open. The quick menu's Databases items call `pickDb` when the page is already open.
- **The page's data:** `renderPage()` draws from the data that `refresh` loaded. A state that changes between refreshes, such as the download's progress, must be read from `S` directly.
- **Disabled menu items:** WebKit may show no `title` tooltip on a disabled button. The reason is still in its `title` for assistive technology.
