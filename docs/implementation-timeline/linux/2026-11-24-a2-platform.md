# Phase 13 A2: the Linux platform layer by capability, for Arch

> Date: 2026-11-24 · PRs: #137 (branch `arch-a2`), hadziqmtqn/devid-binaries#23 (branch `arch-fonts`) · Plan and results: `docs/roadmap/phase-13.md`, "A1 results" and "A2 results" · Decision: D-059

## What shipped

- **`platform/linux.rs` reads the system into `System`:**
  - which CA store it has;
  - whether systemd-resolved runs, and whether Devid turned it on;
  - the sockets that start resolved;
  - whether `/etc/resolv.conf` has a backup or is the stub link.

  `install_actions_on` and `uninstall_actions_on` take it, so the tests set each case directly. `install_actions` and `uninstall_actions` read it from the system.
- **CA:**
  - **Debian:** unchanged.
  - **Arch:** the CA goes to `/etc/ca-certificates/trust-source/anchors/devid-ca.crt`, then `update-ca-trust extract` runs. Status reads that copy.
- **DNS where systemd-resolved is off:**
  - **Setup:** writes `/etc/devid-resolved.state` first, then the drop-in. It enables and restarts resolved, links `/etc/resolv.conf` to `../run/systemd/resolve/stub-resolv.conf` (backed up once), and runs `systemctl try-restart NetworkManager.service`.
  - **Uninstall:** puts back the backup, or removes a link with nothing behind it. It runs `disable --now` on resolved and its `TriggeredBy` sockets, restarts NetworkManager and removes the note. The "resolver" status also needs resolved to run.
- **`helper.rs`:**
  - new: `Link` and `Restore`, and `backup_path` and `present`;
  - changed: `Remove` checks with `symlink_metadata`, so a dangling link counts as present.
- **Prerequisites:**
  - `prerequisites_on` checks systemd, nftables and either CA tool, and names them with apt or pacman;
  - with resolved off, NetworkManager must run.

  certutil's and the fonts' hints follow pacman too, and the DejaVu check knows `/usr/share/fonts/TTF/`.
- **The terminal:** `terminal_for` picks one, in this order:
  1. `x-terminal-emulator`;
  2. `$TERMINAL`;
  3. konsole, gnome-terminal, kgx, xfce4-terminal, alacritty, kitty, foot or xterm, with each one's working-folder option.
- **fish:**
  - `install::rc_files_for` gives fish `~/.config/fish/conf.d/devid.fish` on every OS. `rc_line(paths, rc)` writes `fish_add_path --global --move --path '<bin>' # added by devid` there and `export PATH=…` elsewhere.
  - `rc_has_line(paths, rc)` replaces the shared line in setup, doctor, `devid path` and the daemon's `terminal_status`. `ensure_rc_line` creates the folder.
  - `DEVID_LOGIN_SHELL` comes before the user database.
- **`main.rs`:** the dry runs no longer need the CA. Only a real `helper install` checks for it and the prerequisites.
- **`scripts/linux-e2e.sh`** snapshots more:
  - `/etc/resolv.conf`, as a link or as content;
  - whether `systemd-resolved` and its two sockets are enabled and active;
  - the Arch CA copy, the note and the backup.

  It also takes Firefox's profile from where each system keeps it, and uses `chromium` where `google-chrome` is missing.
- **devid-binaries#23:** `extensions/imagick/type-linux.xml` lists its nine fonts again with Arch's paths, and its README says so.

## Gotchas

- **`Path::exists` follows links.** A backup that is a dangling link looked absent, and `Remove` with a restore would then have deleted `/etc/resolv.conf`. `present` uses `symlink_metadata`.
- **The uninstall plan depends on what setup left.** The plan is read as root at apply time: the note, the backup and the sockets. A dry run as the user reads the same files.
- **`systemctl disable --now` with the sockets named** still warns that the service's triggering units are active, before the sockets stop.
- **Arch's `/etc/skel` has `~/.bash_profile`,** so login shells never read `~/.profile`, and `~/.bashrc` returns early in non-interactive shells. This is left for A1.6 on the KDE Plasma machine.
