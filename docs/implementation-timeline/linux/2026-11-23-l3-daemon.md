# Phase 12 L3: the daemon, the CLI and the TUI on Linux

> Date: 2026-11-23 · PR: #125 (branch `linux-daemon`, merged as 66018a4) · Design: `docs/roadmap/phase-12.md`, "L3 design"

## What shipped

- **`crates/daemon/src/platform/`:** everything that differs by OS.
  - `macos.rs` holds code moved unchanged from `helper.rs`, `install.rs` and `ondemand.rs`: the resolver file, pf, the keychain, the LaunchAgent and libproc.
  - `linux.rs` is new.
  - `mod.rs` re-exports the current system's functions.
  - Both files compile on both systems; only the libproc calls are behind `cfg`.
- **`helper.rs`** keeps the plan, validation and `apply`. It gains `Action::Copy` for the CA certificate, made readable by all.
- **The Linux root step** (`sudo devid helper apply`):
  - `/etc/systemd/resolved.conf.d/devid.conf`, then a restart of systemd-resolved. An existing file is backed up.
  - `/etc/devid-ports.nft`, the `inet devid` table, and `/etc/systemd/system/devid-ports.service`, which loads it after `nftables.service` and deletes it when stopped. The unit is enabled and restarted.
  - The CA is copied to `/usr/local/share/ca-certificates/devid-ca.crt`, then `update-ca-certificates` runs.
  - Uninstall reverses each part. Status needs no root: it reads each file and looks for the CA in `/etc/ssl/certs/ca-certificates.crt`.
  - Before `sudo`, setup checks for `systemctl`, `nft` and `update-ca-certificates`, and that systemd-resolved runs.
- **As the user on Linux:**
  - **Chrome:** `certutil` puts the CA in `~/.pki/nssdb`. It creates the database if needed and removes older Devid CAs first. Without `certutil`, setup prints how to install `libnss3-tools` and goes on.
  - **The user unit:** `~/.config/systemd/user/devid.service`.
    - It runs `ExecStart="…/devid" daemon run` with `DEVID_HOME`, `Restart=on-failure` and `KillMode=mixed`, and appends its output to `daemon.log`.
    - Values in the unit are quoted, and `%` is escaped.
    - Setup runs `daemon-reload`, `enable` and `restart`. Uninstall runs `disable --now` and deletes the unit.
  - **PATH:** `~/.bashrc` and `~/.profile` for bash, and `~/.zshenv` and `~/.zshrc` for zsh.
  - **On-demand:** the connection check reads `/proc/net/tcp` and `tcp6`, then matches inodes against `/proc/<pid>/fd` for the group's processes (pgrp read from `/proc/<pid>/stat`).
- **Shared changes:**
  - The manifest arch key comes from `platform::arch_key()`: `x86_64` and `arm64` on macOS, `linux-x86_64` on Linux.
  - `webserver::check` refuses Apache on Linux, and `server list` shows only the servers the system runs. `setup --gui` is refused there too.
  - The TUI and `devid mail open` use `xdg-open`. The TUI opens `x-terminal-emulator` in the site's folder, and copies with `wl-copy`, `xclip` or `xsel`.
  - `doctor` adds the system's own checks: Valet on macOS; Chrome's database and, with imagick installed, the DejaVu fonts on Linux. It names the service and the system in its lines.
  - composer.phar is checked with `releases::sha256_hex`, not `shasum`.
  - A startup file left empty when Devid's PATH line goes is deleted, since Devid created it.
  - Messages say "this computer" instead of "this Mac".
- **CI:** the `linux-e2e` job in `ci.yml`.
  - It builds `x86_64-unknown-linux-musl` and installs `musl-tools` and `libnss3-tools`.
  - Then it runs `scripts/linux-e2e.sh`: lingering, a snapshot of every file setup may change, `devid setup`, `devid link`, curl and headless Chrome, `devid doctor`, and `devid uninstall --purge`, then the snapshot is compared.

## Gotchas

- **`cargo test` stops at the first test binary that fails.** The CLI tests that assumed macOS therefore surfaced one CI run at a time:
  - `ext`, `mail` and `releases`: fake manifests without `linux-x86_64`;
  - `servers`: Apache;
  - `shim` and `system`: the dry runs' macOS steps.

  Locally, `--no-fail-fast` shows them all at once.
- **certutil prints a blank line for an empty database.** The e2e snapshot counts only certificate lines.
- **`devid link` replies once nginx has its SIGHUP, before the new workers run.** A curl right after it got "tlsv1 unrecognized name" in one run. The script waits for the site, as `smoke.sh` does.
- **A runner has no login session,** so the user's systemd runs only with lingering. On a desktop or over SSH, the login starts it.
- **`update-ca-certificates --fresh` rebuilds the bundle byte for byte** without Devid's CA, so the bundle can be compared as a file.
