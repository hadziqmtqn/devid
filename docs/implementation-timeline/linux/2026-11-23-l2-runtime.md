# Phase 12 L2: the Linux x86_64 runtime in `devid-binaries`

> Date: 2026-11-23 · Repository: `devid-binaries` · PR: hadziqmtqn/devid-binaries#19 (5f0f8f9) · Release: `2026.11.23-19`

## What shipped

- **Runners:** `release.yml` builds PHP and nginx on `ubuntu-24.04` next to `macos-15-intel` and `macos-15`. The Linux jobs install `qemu-user`, `patchelf` and `gdb`.
- **PHP 8.3.37, 8.4.28 and 8.5.13** (`build-php.sh`):
  - built with static-php-cli's zig toolchain, `SPC_TARGET=x86_64-linux-gnu.2.17`;
  - the same extensions as on macOS, with Xdebug and pcov as `.so` files;
  - patchelf removes the build root's runpath;
  - archives of 46 to 49 MB.
- **The catalog** (`build-ext.sh`): the eight recipes for each PHP, 24 archives. They are built by the same zig for the same target (`CC="zig cc -target …"`, `-Wno-date-time`) and linked with `-z nodelete` and `-Bsymbolic` (see Gotchas).
  - **mongodb** links libresolv.
  - **swoole** links zig's libc++.
  - **imagick** ships `etc/type.xml` from `type-linux.xml`, which names the DejaVu and Liberation fonts in `/usr/share/fonts/truetype/`.
- **nginx 1.30.7:** fully static with musl, a 2.4 MB archive.
- **Caddy 2.11.9 and Mailpit 1.34.0:** the official `linux_amd64` builds, mirrored and checked like the macOS ones.
- **`manifest.json`:**
  - Linux builds join the same entries under the arch key `linux-x86_64`.
  - `x86_64` and `arm64` stay macOS.
  - `schema` stays 1.
- **Checks on every Linux build:**
  - `scripts/check-linux.sh`: glibc's own libraries only, no glibc symbol newer than 2.17, no rpath. nginx must have no dynamic part at all.
  - php, php-fpm and nginx run under QEMU's Nehalem CPU.
  - **Extensions:**
    - load in php and php-fpm, with and without Xdebug, under `LD_BIND_NOW=1`, so every symbol must resolve at load;
    - the `.so` must be marked `NODELETE` and `SYMBOLIC`;
    - the smoke test runs natively and again under QEMU's Nehalem.
  - A crash (exit 128 or more) prints a gdb backtrace into the job log.
- **Also on macOS:** a failed download in `build-ext.sh` now says so instead of reporting a checksum mismatch, and waits 10 s between retries.

## Gotchas

- **A failing recipe could still pass the job.**
  - 33dd580 ran each recipe in a subshell between `set +e` and `set -e`, so one failure would not stop the others.
  - The subshell inherits `set +e`. A failed check then printed FAIL, but the recipe was still packaged and the job passed. One dry run went green that way.
  - The subshell now starts with `set -e`. The bug never reached a release.
- **imagick and mongodb crashed at exit (exit 139).**
  - PHP unloads extensions with `dlclose` at shutdown. The atexit handlers and C++ destructors of the libraries inside them then ran in code that was no longer mapped.
  - `-z nodelete` keeps the `.so` mapped.
  - `-Bsymbolic` keeps each extension's own OpenSSL and libc++ from binding to PHP's copies.
- **`LIBS` does not reach an extension's link.** PHP's rule that links the `.so` reads `LDFLAGS` and `EXTRA_LDFLAGS`. `LIBS` only affects configure's checks, so mongodb's `-lresolv` goes in `LDFLAGS`.
- **glibc 2.34 and later keep `__dn_expand` and `__res_nsearch` only as versioned compat symbols.** A plain `dlsym` check cannot see the difference. `LD_BIND_NOW=1` checks exactly what the loader resolves.
- **libtool with `zig c++` leaves out libc++,** so swoole links `-lc++` itself.
- **ImageMagick tuned itself to the build machine.**
  - Its configure adds `-mtune=<host CPU>`, which zig treats as the target CPU.
  - imagick built on an AMD runner then died with SIGILL (`extrq`, an AMD-only instruction) on an Intel one.
  - `--without-gcc-arch` fixes it, and the Nehalem smoke test would catch it again.
  - The ImageMagick build stamp now includes the configure arguments, so a cached build is redone when they change.
- **ImageMagick without fontconfig needs a font list.** With no `type.xml` it cannot draw text ("unable to read font"). Fonts the list names but the machine lacks are skipped.
