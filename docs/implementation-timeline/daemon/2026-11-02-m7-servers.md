# M7: Caddy and Apache adapters, `devid server use`

> Date: 2026-11-02 · Branch: `phase2/m7-servers` · Plan: [Phase 2](../../roadmap/phase-2.md)

## Outcome

- `devid server install <nginx|caddy|apache> [--from <binary>]`, `devid server use <name>` and `devid server list`. Only one server runs at a time (D-005); nginx stays the default (D-015).
- A switch is transactional: if the new server rejects its config, the command fails and the old server keeps serving.
- Caddy and Apache configs are rendered from the same site list as nginx, with Devid's certificates and 127.0.0.1-only listeners. Details are in ARCHITECTURE, "Implemented in M7".
- Each service has its own stop signal (SIGQUIT for php-fpm/nginx, SIGTERM for Caddy/Apache) and reload method (SIGHUP for nginx, SIGUSR1 for Apache, restart for Caddy).

## Problems found and fixed

- **Caddy rejected `http://host, https://host` in one block with `tls`.** The fake Caddy in CI does not validate this; real Caddy 2.11.7 did. Each site now gets separate HTTPS and HTTP blocks. The failed switch left nginx serving, so the transactional switch worked as designed.
- **A wrong binary could hang the daemon forever.** `server install caddy --from <nginx>` ran nginx, which ignores `version` and keeps running. All version probes now time out after 5 s; the old `sites` test now asserts that rejection.
- Caddy's regexp engine has no lookahead, so the dotfile rule uses a `path /.*` + `not path /.well-known/*` matcher.

## Verification

- `cargo test`: 25 tests pass.
  - Unit tests render nginx, Caddy and Apache configs, including the injection-skip checks.
  - The new integration test `switch_between_nginx_caddy_and_apache` uses fakes: validation errors, the nginx→Caddy switch (nginx process gone), a Caddy restart on a site change, Apache's graceful reload on a site change, back to nginx, and `server list`.
- Real binaries (nginx 1.30.6 from our build, official Caddy 2.11.7, macOS Apache 2.4.67) in a test home on ports 18088/18443, serving `erdbpro-saas`. **All three are identical:**
  - `/login` 200 over HTTP/2 with the Inertia `data-page`, favicon 200, `/.env` 403, unknown path 404;
  - HTTP 200, and 404 for an unknown host on HTTP;
  - a new site is served after `link` under Caddy (restart).
- Switch time until the site serves again: nginx 0.24 s, Caddy 0.32 s, Apache 0.71 s.
- Idle RAM of the web server: nginx 4.0 MB, Apache 4.9 MB, Caddy 30.3 MB. This confirms D-015.
- The test daemon stopped with no leftover processes. `cargo fmt --check` and `clippy -D warnings` are clean.
