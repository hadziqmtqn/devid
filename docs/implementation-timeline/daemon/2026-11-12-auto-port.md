# A new proxy site gets a free dev server port; `devid cmd <site>` lists (D-042, v0.12.5)

> Date: 2026-11-12 · Branch: `feat/auto-port`

## Why

- Two projects of the same type both forwarded to its default port (Next.js and Node.js: 3000). The owner asked how a project can avoid a port another one uses. D-041 then made commands follow "Forward to", and the owner asked for Devid to pick a free one.
- `devid cmd devid-site` failed with "unrecognized subcommand". The docs say `devid cmd [list] [site]`.

## Change

- **`sites::spread_ports(known, config, busy)`:**
  - **Candidates:** proxy sites with no `[apps.<site>]` in `known` and no `.env` `PORT`. They are taken in folder creation order, then name order.
  - **What it does:** a candidate whose port is already taken (other proxy sites' upstreams, local ports, earlier candidates) gets the next port that is neither taken nor `busy`. That port is saved as `apps.<site>.upstream`.
- **`State::mutate`:** runs it with the config before the change as `known`, so a new site's first `cmd add` still counts as new.
- **`server::run`:** runs it at start and saves the config when a site moved. The daemon log names each moved site.
- **CLI:** `devid cmd <site>` (`args_conflicts_with_subcommands`) lists that site's commands, as `devid cmd list <site>` does.
- **Version:** 0.12.5. **Decision:** D-042, which amends D-035.

## Verification

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`: pass.
- **New unit test `spread_ports_moves_only_new_sites_on_a_taken_port`:**
  - a site with settings and a site with `.env` `PORT` keep their ports;
  - a new site whose first command this change saves moves (3000 taken, 3001 `.env`, 3002 busy → 3003);
  - of two new Vite folders, the older keeps 5173, unsaved, and the newer gets 5174;
  - a second run moves nothing.
- **New integration test `a_new_project_gets_a_free_dev_server_port`:**
  - two Next.js folders are parked: the older keeps 3000, and the newer gets a higher port, saved in `config.toml`;
  - `devid cmd b-new` lists that site.
  - On the owner's Mac it got 3002, because 3001 was in use.
- **Mutation checks:**
  - without the call in `mutate`, the integration test fails;
  - with name order in place of creation time, the unit test fails.
