# M6: setup, doctor, uninstall, LaunchAgent and shims

> Date: 2026-11-02 · Branch: `phase2/m6-setup` · Plan: [Phase 2](../../roadmap/phase-2.md)

## Outcome

- **The daemon stops cleanly on signals.** SIGTERM (launchd), SIGINT and SIGHUP trigger the same shutdown as `devid daemon stop`, so PHP and nginx stop and the socket is removed. This replaces the M3 `shortcut:`.
- **`devid setup`** is idempotent and supports `--dry-run`:
  1. installs `~/.devid/bin/devid` plus the `php` and `composer` shims;
  2. adds a marked PATH line to `~/.zshrc`;
  3. hands a hand-started daemon over to the LaunchAgent `dev.devid.daemon` (starts at login, restarts on a crash, stays down after `devid daemon stop`);
  4. downloads `composer.phar` (sha256-checked);
  5. runs `devid helper install` only if the system pieces are missing.
- **`devid doctor`** checks, read-only, with a fix for each problem:
  - PATH: `devid` and `php` resolve to Devid, not Homebrew;
  - the LaunchAgent, the daemon, DNS, nginx and the default PHP;
  - the helper pieces, `.test` resolving through macOS, and the CA;
  - Valet's dnsmasq still running.
- **`devid uninstall [--purge]`** runs `helper uninstall` (restoring Valet's resolver), unloads and removes the LaunchAgent, removes the PATH line, and deletes `~/.devid/bin`. `--purge` deletes all of `~/.devid`.
- **Shims:**
  - `php` picks the site's isolated version (also from a subfolder), otherwise the default, and uses Devid's ini;
  - `composer` uses `composer.phar` with that PHP;
  - a missing version or phar gives a clear error.

## Problems found and fixed

- **Children inherited the daemon's blocked signals,** so nginx never got SIGHUP and reloads stopped. The supervisor now clears the mask before exec. (A comment had wrongly assumed that std resets it.)
- **`devid daemon stop` could report failure on a stop that worked.** The `stop` handler woke the accept loop before writing its reply, so the daemon could exit first and the client read an empty reply. CI on Linux caught it; on macOS the timing happened to win. The reply is now written before the loop is woken.
- **The tests were not hermetic once the real Devid ran on this Mac.** Test daemons hit the real DNS port 53535, and the real pf redirect made test URLs drop their ports. Test daemons now use their own ports (18088/18443 and a free DNS port).

## Owner run (2026-11-02)

- The owner ran `devid setup`. All steps passed; the system part was "already in place", so there was no password prompt.
- launchd now runs the daemon, `composer.phar` was downloaded, and the site still returns 200.
- In the terminal that was already open, `devid` was "command not found" and `php` was still Homebrew's: an already-open shell does not re-read `~/.zshrc`. A fresh `zsh -i` resolves `devid` and `php` to `~/.devid/bin`. `doctor` now says "open a new terminal or run `exec zsh`" when the rc line exists but is not loaded, instead of "run `devid setup`".
- The doctor check for Valet was renamed to "Valet is stopped" so a failure reads correctly.

## Follow-up: upgrade via `devid setup` (fix/agent-reload)

- **The first upgrade took the sites down for about a minute.** `launchctl bootout` returns before launchd has released the job, and the `bootstrap` right after failed with "Bootstrap failed: 5: Input/output error". The agent was restored by hand.
- **Fix:** `unload_agent` now waits until `launchctl print` no longer finds the job (up to 20 s), and `load_agent` retries `bootstrap` (10 tries, every 0.5 s).
- **Verified:**
  - re-running `devid setup` on the owner's Mac upgraded the running agent without manual help;
  - a test agent (other label, ports and home) restarts in 0.95 s from bootout to the first 200;
  - the daemon itself exits 0.1 s after SIGTERM with real nginx and PHP.
- On the real site the PHP gap was about 1 s (php-fpm log 16:55:38 → 16:55:39). The probe's failures afterwards came from its own 1 s timeout while 4 cold Laravel workers (`pm.max_children = 4`) were saturated by a request every 0.2 s, not from an outage.
