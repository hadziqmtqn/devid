# M4: local CA and HTTPS

> Date: 2026-11-02 · Branch: `phase2/m4-https` (stacked on M3) · Plan: [Phase 2](../../roadmap/phase-2.md)

## Outcome

- The daemon creates the **Devid Local CA** on first start: an ECDSA P-256 key in `~/.devid/ca/devid-ca.key`, created with mode 0600, valid for 10 years with `pathlen=0`, **name-constrained to `.test`**. The key alone is enough to sign new leaves after a restart.
- Every site gets a leaf certificate in `~/.devid/certs/<host>.{crt,key}`:
  - SAN, `serverAuth` EKU and AKI;
  - valid 397 days counted from `not_before`, and renewed 30 days before expiry;
  - a unique serial per certificate.
- `cacert.pem` now holds the system bundle plus the Devid CA, so PHP trusts site-to-site HTTPS (D-008).
- nginx listens on `127.0.0.1:8443` (`https_port`) with `ssl` and `http2` for every site. Unknown hosts get `ssl_reject_handshake`.
- `devid status` shows the HTTPS port and the CA path. `devid sites` shows the HTTPS URL plus `http_url` in JSON.
- New dependencies: `rcgen` 0.14 with the **ring** backend (the default aws-lc-rs needs a cmake C build on every machine and in CI) and `time`.

## Verification

- `cargo test`: 10 tests pass.
  - The CA unit test checks the leaf independently with `openssl verify -purpose sslserver`, checks the SAN and EKU in `openssl x509 -text`, checks that both keys are mode 0600, checks that an expiring leaf is reissued, and checks that `cacert.pem` ends with the Devid CA.
  - The sites integration test checks that every site has a certificate and that `cacert.pem` contains the CA.
- Manual check with real binaries in the demo home:
  - `https://erdbpro-saas.test:8443/login` and `https://demo-laravel.test:8443/` return 200 over HTTP/2 with `--cacert`;
  - without the Devid CA, curl fails (60); an unknown host has its handshake refused (35);
  - PHP 8.5 calls `https://erdbpro-saas.test:8443` (served by PHP 8.4) and gets 200, using only `curl.cainfo` from php.ini;
  - HTTP on 8088 still works.
- `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` are clean.

## Problems found with Apple's verifier (fixed)

- **Lifetime.** `security verify-cert` rejected the first leaves with `OtherTrustValidityPeriod`. `not_before` was backdated a day while `not_after` was counted from now, which made the lifetime 826 days, over Apple's 825-day limit. The lifetime now counts from `not_before` and is 397 days, clear of the stricter limits Apple and browsers are moving to.
- **Name constraints.** Once trusted, an unconstrained local CA could sign for any domain. The CA is now constrained to `.test`. Apple's verifier accepts `erdbpro-saas.test` ("certificate verification successful") and rejects a `www.example.com` leaf from the same CA ("Certificate violates name constraints placed on issuing CA"). The unit test checks the same with `openssl verify`.

## Not yet

The CA is not in the system trust store, so browsers show a certificate warning until M5 (helper) or a manual trust step.
