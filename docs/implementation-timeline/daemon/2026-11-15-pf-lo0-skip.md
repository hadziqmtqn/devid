# Fix: ports 80/443 are checked live, and `helper install` undoes `skip on lo0` (D-047)

> Date: 2026-11-15 · Branch: `fix/pf-lo0-skip`

## Problem

The competitor research turned up Yerd issue #253. When another pf client sets `skip on lo0`, the `rdr … on lo0` rules stop matching. macOS Internet Sharing does that when OrbStack, Docker or UTM adds a VM network. Devid uses the same kind of rules, and nothing in Devid would have noticed.

## Findings

The owner ran a script that changes only pf options (`pfctl -O`) and restores them on exit (macOS 14.8.9):

| Step | `lo0` | 127.0.0.1:80/443 | nginx 8088/8443 |
|---|---|---|---|
| Before | filtered | open | open |
| `set skip on lo0` | skip | refused | open |
| Devid's anchor reloaded (what `setup` and the LaunchDaemon do) | skip | refused | open |
| `pfctl -O -f /etc/pf.conf` | filtered | open | hang (see ARCHITECTURE Unknowns) |

Other findings:
- The owner's Mac has no OrbStack, Docker or VM, so it was not affected before the test.
- A user process can bind `*:81` but not `127.0.0.1:81` on macOS 14.

## Fix

- `webserver::NO_SITE`: the catch-all reply to a host with no site. nginx, Caddy and now Apache (`ErrorDocument 404`) send the same text. Apache's reply was checked with the system httpd on a spare port.
- `webserver::answers_on(port)`: sends `GET /` for `devid-probe.invalid` to 127.0.0.1:`port` and looks for that text. Another server on the port does not pass.
- Status `standard_ports_ok`: null without the pf redirect or a running web server. Otherwise the probe result, cached for 15 s, with a second try after 300 ms.
- `devid status` prints a `ports:` line when the check fails.
- The TUI header shows `✗ 80/443 not redirected`, and the Server page gives the fix.
- The app shows a banner on every page, and the Web Server page shows "not working".
- The menu-bar icon turns red, and its menu starts with "Sites do not answer on ports 80 and 443".
- `devid doctor` adds the check "ports 80/443 reach <server>". Its fix is `devid helper install`.
- `helper install` runs `pfctl -O -f /etc/pf.conf` after loading the anchor, but only when `pfctl -s Interfaces -v` shows `lo0 (skip)`. The step may fail without stopping the install.
- `devid setup` checks before it restarts the daemon, and runs the sudo step when port 80 does not answer, even if every file is in place.
- Tests:
  - `answers_on_needs_devids_own_reply`: Devid's reply, another server's reply, and a closed port.
  - The helper test checks the unskip step.
  - The TUI test checks the header and the Server page.
  - `system.rs` checks that `standard_ports_ok` is null without pf.
- Live, read-only, on the owner's Mac with the new build: `devid doctor` printed `ok  ports 80/443 reach nginx`.
